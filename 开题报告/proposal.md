# 本科毕业设计开题报告

**课题名称：基于贪心、遗传与模拟退火混合算法的高校排课系统的设计与实现**

学生：（待填）　指导教师：（待填）　专业班级：软件工程 B232 班

撰写日期：2026 年 11 月

## 一、选题依据

高校排课需要将教学任务分配到有限的时间和教室，并满足教师、班级、场地和教学计划的要求。修改一项安排可能影响其他课程，因此需要自动生成课表并在调整时检查冲突。本课题以本人所在大学为调研对象，从信息工程系的本科行政班开始试点，结合学校实际课程和教学场所开展设计。

目前已收集院系、专业、教室名单及三份课程评估表，并记录了 2023 级软件工程 B231、B232 两个班级。每班 48 人暂作为建模假设。教室名单不能直接提供容量，课程评估表也不能替代学期教学任务；任课教师、周学时、周次、连堂要求和可用时间等字段仍需核实补充。

研究目标是实现可部署的 Web 排课系统，重点解决可行课表构造、软约束优化和调整后的冲突检测，并通过实验评价混合算法的收益和成本。

## 二、国内外研究现状

教育时间表问题包含课程排课和考试编排等不同类型。高校课程排课通常同时涉及教师、班级、教室、周学时和课程分布要求。公开的课程排课模型和教育时间表综述可为约束分类、评价指标及实验设计提供参考 [1][2]。

已有方法包括贪心启发式、遗传算法、模拟退火和混合搜索。贪心可用于较快构造初始课表；遗传算法通过种群和遗传操作探索不同方案；模拟退火通过邻域移动及一定概率接受较差方案进行搜索。各方法的效果依赖编码、约束处理和参数，组合使用是否有益需要实验验证。

已收集的《改进遗传算法求解新高考背景下的排课问题》研究高中走班场景，可作为遗传操作和约束处理的参考，其规则需根据高校行政班场景重新设计 [3]。开源 CourseArragement 项目可作为导入、课表展示和排课流程的工程参考，引用或复用时记录来源，遵守原项目许可证 [4]。

本课题采用成熟算法开展工程实现与实证比较，贡献重点为本校场景的约束建模、混合求解流程和可解释的排课结果。

## 三、研究内容

### 3.1 系统范围

面向普通本科大一至大四，以一个学期的行政班周课表为对象，先在本校信息工程系选取试点数据。首版支持课程的起止周、单双周、每周课时和连续节次要求；任课教师和上课班级由教学任务预先指定。公共课涉及试点范围以外的教师或教室时，录入已有占用以避免资源冲突。

管理员维护数据、执行排课和发布课表；教师与学生通过同一 Web 系统查询相关课表。首版采用固定行政班教学模型，走班、复杂跨专业合班和多校区通勤作为后续扩展。

### 3.2 约束建模

硬约束：同一实际教学周和节次内，教师、班级和教室分别不得重复占用；教室容量与类型满足要求；课程满足教学任务规定的周学时、周次和连堂长度；固定安排及不可用时段得到遵守。

软约束：课程在一周内适当分散，减少教师和班级的课表空档，减少连续授课过长的情况，尽量满足教师时间偏好。软约束阈值和权重根据学校规则确定。

### 3.3 混合算法

统一采用“教学活动 → 星期、起始节次、教室”的编码。一个教学任务可按每周授课次数拆成若干活动，每个活动携带周次集合及连续节数。两个活动的时间冲突须同时检查周次交集与节次重叠。

1. **贪心初始化**：先处理固定活动，再按候选位置少、资源竞争高等规则排列活动，逐个选择满足硬约束且软代价较低的位置。通过随机化并列候选生成多个初始个体，增加种群多样性。构造失败时记录未排活动及受限原因。
2. **遗传优化**：以完整课表为个体进行选择、交叉、变异和精英保留。交叉或变异后调用统一校验器，使用受限修复调整冲突活动；无法在预算内修复的子代不进入可行种群。种群不足时重新构造，仍不足则报告失败。
3. **模拟退火改进**：对遗传阶段的最优可行个体执行移动和交换搜索。先校验硬约束，再依据软代价变化与温度决定是否接受，保留历史最优可行方案。按迭代次数或时间预算停止。

三个阶段共享编码、约束校验和评价函数，采用硬约束可行性优先的评价方式；对不可行结果明确报告，不作为可发布课表。初始化及修复均设置次数限制，构造失败不等同于证明数学上无解。

### 3.4 Web 功能

系统围绕六项功能实现：基础数据维护与 Excel 导入、教学任务与约束设置、自动排课、手动调整与冲突提示、课表发布与查询、Excel 导出。算法参数提供默认值，仅保留必要配置。首版不预先承诺模块数量和表数量，以业务流程闭环为准。

## 四、研究方案

### 4.1 技术路线

学校调研与数据核实 → 教学活动及约束建模 → 贪心构造 → 遗传优化 → 模拟退火改进 → Web 调整与发布 → 对比实验。

系统采用浏览器/服务器架构，后端 Java、Spring Boot，前端 Vue 3，数据库 MySQL。求解器作为独立模块，输入教学活动、资源和参数，输出课表、未排原因与评价指标。Web 端在排课期间显示任务状态，支持固定时间预算。部署到自有云服务器，提供统一 Web 入口。

### 4.2 数据方案

以本校已收集的院系、专业、教室和课程资料为来源，补充一个学期的教学任务。优先收集班级人数、任课教师、周学时、起止周、单双周、连堂要求、教室容量和类型、作息时间及不可用时段。采用匿名编号处理师生信息。

真实数据不足时补充可复现的模拟实例，明确标记真实字段、暂定值和模拟字段，不将课程评估记录直接视为完整教学任务。按教学活动数、资源数量和冲突密度形成小、中、大三组实例，具体规模在数据核实后确定。

### 4.3 实验方案

设置四组：贪心、贪心初始化加遗传算法、贪心初始化加模拟退火、贪心加遗传加模拟退火。各组采用同一编码、约束、数据和软约束权重，并在相同硬件、总时间预算下比较，记录实际耗时和停止条件。

评价指标包括可行解成功率、未排活动数、硬冲突数、软约束代价和运行时间。每组采用相同的预设随机种子集合独立运行多次，报告均值、标准差和最优值；校验器独立复查输出课表。对于未得到可行解的运行，单独报告，不与可行方案的软代价混算。

通过遗传与退火阶段的消融比较判断其贡献，并分析资源紧张程度和不同参数对结果的影响。若混合算法未表现出稳定优势，据实报告结果及适用条件。

### 4.4 可行性与风险

现有仓库具有工程骨架和学校调研资料，业务模块及算法尚待实现。主要风险是教学任务不完整和混合搜索调参成本，拟通过单系试点、统一校验器、分阶段可运行实现及固定预算实验控制范围。先完成贪心排课的 Web 闭环，再加入遗传和退火阶段。
