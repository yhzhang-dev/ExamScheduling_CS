# 高校遗传算法排课系统功能设计

课题：基于遗传算法的高校排课系统的设计与实现。

## 范围

本校普通本科、大一至大四，单学期行政班课表，先选信息工程系试点。Web 系统统一服务管理员、教师和学生。任课教师、班级由教学任务指定，公共资源的外部占用作为输入。

## 功能

| 功能 | 首版内容 |
|---|---|
| 基础数据 | 班级、教师、课程、教室维护及 Excel 导入 |
| 教学任务 | 学期、任课教师、班级、周次、周学时、连续节数 |
| 约束配置 | 作息时间、固定安排、不可用时间、容量与场地类型 |
| 自动排课 | 种群初始化 → 遗传迭代 → 冲突校验；记录耗时与未排原因 |
| 调整发布 | 手动移动、交换前校验冲突；发布前全量复查 |
| 查询导出 | 按班级、教师、教室查询周课表；Excel 导出 |

## 算法与数据

教学活动编码为星期、起始节次、教室，并携带周次集合和连续节数。仅在周次及节次均重叠时检查资源冲突。统一校验器负责教师、班级、教室唯一占用，容量、类型、课时、周次和固定安排。

随机初始化种群，采用可行性优先的适应度评价；执行选择、交叉、变异和有限冲突修复，并保留精英及历史最优可行课表。固定活动不参与变更，设置代数与时间预算，发布前独立全量校验。

软目标为课程分散、减少空档及合理连续授课，具体权重待核实学校规则。失败输出未排活动与限制原因，不把搜索失败解释为已证明无解。

## 实现顺序与实验

基础数据和教学任务 → 独立校验器 → 遗传排课与 Web 闭环 → 部署与实验。

比较简单贪心基线与遗传算法，相同数据、权重、总时间预算和随机种子集合。报告成功率、未排数、冲突数、软代价和耗时。实现细节以[开题报告](../../开题报告/proposal.md)为准。
