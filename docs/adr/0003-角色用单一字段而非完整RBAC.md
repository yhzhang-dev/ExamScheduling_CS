# 角色用单一 `role_code` 字段，不启用完整 RBAC

## 背景

系统有三个角色：教务管理员、教师、学生。旧代码的 `app_user` 只有 `role_code`（`ADMIN`/`USER`），鉴权过滤器与前端都按这个字段判断。建新表时同时准备了 `role` / `user_role` / `permission` / `role_permission` 四张权限表。

## 决策

把 `role_code` 扩展为 `ADMIN` / `TEACHER` / `STUDENT` 三个值，权限判断只读这一个字段。四张权限表保留在 schema 里但**暂不启用**。

## 为什么

三个角色的权限差异是「看到不同页面、调不同接口」，不存在「同一角色内部权限不同」的需求。完整 RBAC 会让每条接口多一层权限查询，而它解决的问题在本项目里不存在。

## 后果

- 读到 `role`、`user_role`、`permission`、`role_permission` 四张空表时，不要以为实现没接完——这是刻意的（容易误判，故立此 ADR）。
- 若将来出现「同角色不同权限」的真实需求（例如院系管理员只能看本院数据），升级路径是把 `role_code` 作为兼容字段保留，以 `user_role` 为权威，逐接口迁移，不推倒重来。

## 考虑过的选项

**完整 RBAC**：更通用，也更像"权限系统"该有的样子，能写进论文；代价是鉴权链路、前端菜单、测试三处都要多一层，收益与需求不匹配。
